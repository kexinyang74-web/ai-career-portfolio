## 1. Function Calling 是什么？和直接 Chat 有什么差别？

可这样答：还是同一个 Chat 接口。差别是请求里多带一份工具菜单（schema）。模型这轮可以返回给人看的 `content`，也可以返回 `tool_calls`（要点哪个工具、参数是什么）。真正跑函数的是我们的 Python，不是模型自己去干活。

## 2. `tool_calls` 是什么意思？

可这样答：是模型这轮的点菜单，不是已经做完的结果。里面是工具名和入参。读到它，应该去执行函数，不要当成最终回答交给用户。

## 3. 模型返回 `tool_calls` 时，谁真正执行函数？它为什么不能自己去网上抓热点？

可这样答：我们写的 Python 执行。模型没有浏览器，也没有我们的文件权限。接口只返回「请调用」，热点列表要等我们的函数去请求。

## 4. schema 是什么？谁来写？

可这样答：工具菜单的规格说明书：名字、干什么、入参有哪些、类型、哪些必填。菜单是我们事先定义的，模型不能凭空发明新工具。

## 5. `description` 和 `parameters` 各干什么？描述写糊了会怎样？

可这样答：`description` 说明这个工具干什么、什么时候该用。`parameters` 说明入参长什么样（字段、类型、必填）。描述糊了，模型容易选错工具，或该调却不调。

## 6. 入参是什么？举一个项目三的例子。

可这样答：调用函数时传进去的值。比如抓热点函数要 `platform="bilibili"`，这个字符串就是入参。模型填在 `tool_calls` 的参数里，我们的代码拿去调用函数。

## 7. 一轮请求结束后，怎么判断该把回答给用户，还是该去跑工具？两者能同时当「做完了」吗？

可这样答：回包里有 `tool_calls` 就去跑工具，还没结束。没有 `tool_calls`、有给人看的 `content`，才给用户。有点菜单就不能当收工，哪怕旁边有一句「我去抓热点」。

## 8. 工具跑完后，下一次请求的 `messages` 里至少要多哪两类？只把结果当用户新说的一句话行不行？

可这样答：要补上一条带 `tool_calls` 的 assistant，再补 `role=tool` 的结果，用编号对上刚才那次点菜。只当新的用户消息丢回去，模型会分不清这是新需求还是工具刚跑完的观察。

## 9. 和项目二 RAG 比：谁决定「下一步干什么」？

可这样答：RAG 是提问前我们就检索完，片段塞进本轮用户消息。Agent 是对话当中由模型决定调不调、调哪一个，我们只执行它点名的那个。

## 10. 举一种 Function Calling 仍然会失败的情况。

可这样答：任举一个就行。例如该抓热点却点了写日报；入参填成胡编的平台名，函数接不住；抓取报错了却回传「成功」，后面的日报就是假的。
