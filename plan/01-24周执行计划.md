# 24 周执行计划（全职，每天约 8 小时）

## 每日时间块

| 时段 | 内容 | 说明 |
|------|------|------|
| 4 小时 | 动手写代码 | 当天任务的核心产出，只写不看的环节 |
| 2 小时 | 理论 / 官方文档 | 配合动手内容，文档优先于视频 |
| 1 小时 | 面试题积累 | 每天 1-2 道，进面试题库模板 |
| 1 小时 | 学习笔记 | 输出到 GitHub，含当天代码与思考 |

每周 6 天学习、1 天复盘。周日晚上只做一件事：更新进度追踪表 + 写周复盘。

---

## 阶段一：第 1 周｜定位与工程环境

**本周目标**：确定岗位画像，搭好环境，建立"AI 操作、你监督"的 Git 工作流，开一个"门面"仓库。

- [ ] 在 Boss直聘/拉勾搜"AI 应用开发""大模型应用开发""AI Agent 开发"，收集 10 个 JD，整理共同技能要求（写进学习日志）
- [ ] 注册 GitHub；新建仓库 `ai-career-portfolio`
- [ ] 理解 Git 心智模型：工作区 → 暂存区 → 版本库；本地与远程；分支是"指向某个提交的指针"
- [ ] 学会"读"Git：`git status`、`git log --oneline`、`git diff` 能看懂（这是监督 AI 的检查单）
- [ ] 掌握关键词汇：commit / branch / merge / push / pull / remote / 冲突 / Pull Request
- [ ] 让 AI 代跑一遍 init → add → commit → push → clone → branch，你在旁边观察每一步的变化并验证结果
- [ ] 安装 Python 3.12+、VS Code + Python 插件；学会 `venv`、`pip install`、`requirements.txt`
- [ ] 学会用 `.env` 保存密钥，理解"密钥绝不提交到 Git"
- [ ] 写下"作品三件套"目标（参照项目规格书），推第一篇学习笔记到 GitHub

**检查点**：能读懂 `git status` 和 `git log`，能向 AI 准确描述一次操作（例如"把最近的修改提交并推送"）；**不要求手敲命令**。

## 阶段四：第 8-10 周｜RAG 专项

### 第 8 周：原理与手写实现

- [ ] 理解 Embedding、向量相似度（余弦）、向量数据库的作用
- [ ] 手写最小 RAG：读文档 → 切分 → 调用 Embedding API → 向量检索 → 拼进 prompt
- [ ] 对比"直接问大模型"和"RAG 后回答"的效果差异

**检查点**：不依赖 LangChain 等框架，能独立跑通 10 个文档的检索问答。

### 第 9 周：工程化 RAG

- [ ] Chroma 持久化、元数据过滤、top-k、重排（rerank）概念
- [ ] LangChain 入门：Loader / TextSplitter / VectorStore / RetrievalQA
- [ ] 项目二 MVP：加载你的行业文档 → 知识库问答（先做 CLI 版）
- [ ] 【新增】向量库对比：同一批文档用 FAISS 再跑通一遍检索，能说清 Chroma / FAISS / Milvus 的差异与适用场景（对应聚云等 JD 的 FAISS/Milvus 要求）
- [ ] 【可选】NL2SQL 小脚本：用 LLM + 表结构提示词实现"自然语言 → SQL"查询脚本（对应聚云 JD）

**检查点**：能解释不同切分策略（固定长度/按段落/语义）对回答质量的影响。

### 第 10 周：项目二收尾与评估

- [ ] 准备 30 条测试问题，建立人工评测集（可接受/不可接受 + 备注）
- [ ] 调优：切分大小、重叠、检索数量、prompt 中引用格式
- [ ] 目标：30 条问题中至少 70% 回答可接受，且回答能给出引用来源
- [ ] 【新增】评估升级：评测集增加"引用命中率"指标（回答是否正确引用来源文档），按"回答可接受率 ≥ 70% + 引用命中率"双指标产出评估结论
- [ ] 【可选】了解 GraphRAG 概念与适用场景（对应熵检/弋途 JD 的 GraphRAG/知识图谱要求）
- [ ] README + 演示 + GitHub 推送

**检查点**：能回答"RAG 为什么能减少幻觉、什么时候会失效"。
