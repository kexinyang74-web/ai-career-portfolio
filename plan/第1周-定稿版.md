## 一、本周目的

**用一周时间，把"转行工程"的基建搭好，并建立一套和 AI 协作的日常流程。**

具体来说，这一周结束时要达到 4 个状态：

1. 明确自己瞄准什么岗位、市场要什么技能（不再迷茫）
2. 有一个公开的 GitHub 仓库，能持续沉淀学习记录和作品（作品集门面）
3. 能用"AI 操作、你监督"的方式安全地管理代码（不背命令也能干活）
4. 本地开发环境能跑起来，拿到 API 密钥就知道怎么安全保存

这一周不做：不学任何 AI/大模型知识、不写业务代码。基建先行，避免后面边学边补环境。

## 三、任务清单（含目的与耗时）

### 任务 1：岗位调研，收集 10 个 JD
- 操作：在 Boss直聘/拉勾搜"AI 应用开发""大模型应用开发""AI Agent 开发"，收集 10 个 JD，整理共同技能要求，写进学习日志
- 目的：明确市场真实要求，让后面 23 周的学习有的放矢；避免按自己想象学
- 预计耗时：1-2 小时
- 产出物：一篇"岗位要求清单"学习笔记

### 任务 2：注册 GitHub，新建仓库 `ai-career-portfolio`
- 操作：注册账号，新建 Public 仓库
- 目的：这是你未来 6 个月所有学习记录和 3 个作品的展示窗口，面试官会看
- 预计耗时：30 分钟
- 产出物：一个空的 GitHub 仓库

### 任务 3：理解 Git 心智模型
- 操作：弄懂三件事——工作区 → 暂存区 → 版本库；本地与远程；分支是"指向某个提交的指针"
- 目的：有了心智模型，AI 做什么你都能看懂；这是"监督 AI"的地基
- 预计耗时：1 小时
- 产出物：能用自己的话讲清这三件事

### 任务 4：学会"读"Git 状态
- 操作：学会看懂 `git status`、`git log --oneline`、`git diff`
- 目的：这三条命令是检查单——AI 提交/推送前，靠它们确认改了什么、有没有误提交敏感文件
- 预计耗时：1 小时
- 产出物：能独立解读一次 status/log/diff 的输出

### 任务 5：掌握关键词汇
- 操作：commit / branch / merge / push / pull / remote / 冲突 / Pull Request，每个词能说一句人话解释
- 目的：面试与团队协作的日常词汇，也是你向 AI 下达指令的"通用语言"
- 预计耗时：30 分钟
- 产出物：词汇表笔记

### 任务 6：让 AI 代跑一遍完整流程
- 操作：让 AI 执行 init → add → commit → push → clone → branch，你在旁边观察每一步变化并验证
- 目的：在真实仓库上建立"AI 操作、你审核"的协作节奏，这是你以后每天的工作方式
- 预计耗时：1-2 小时
- 产出物：仓库里有第一条真实提交记录

### 任务 7：安装 Python 环境
- 操作：Python 3.12+、VS Code + Python 插件；学会 `venv`、`pip install`、`requirements.txt`
- 目的：项目一从第 5 周就要跑代码，环境提前备好，不占用学习时间
- 预计耗时：1-2 小时
- 产出物：能在虚拟环境里安装依赖并运行脚本

### 任务 8：学会用 `.env` 保存密钥
- 操作：学会把 API 密钥放 `.env`，理解"密钥绝不提交到 Git"
- 目的：第 5 周开始调 API 天天要用；这也是安全底线，避免密钥泄露到公开仓库
- 预计耗时：30 分钟
- 产出物：一个配置好 `.gitignore` 的本地项目

### 任务 9：确定"作品三件套"目标，推第一篇笔记
- 操作：参照项目规格书，写下三个项目的行业主题与大致方向；把本周第一篇学习笔记推上 GitHub
- 目的：三个项目是简历的核心，越早定主题，后面每周的学习越有方向感
- 预计耗时：1-2 小时
- 产出物：作品三件套目标文档 + 第一条 GitHub 提交
