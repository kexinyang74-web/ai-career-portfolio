# 后半程第 2 周计划（定稿）

> 任务说明看本文件；进度打勾见 [[后半程-第2周-进度追踪]]（待建）。正本 = `学习安排\`。
> 对应 [[求职向-后半程]] 的「第 2 周：从空目录搭最小 FastAPI 服务，做创建/查询/修改/删除四个接口」。
> 日历参考 10/8–10/14；实际按 Day 8–14 走，差一两天没关系。

## 本周目的

把第 1 周"**看得懂**"的 FastAPI 请求链路，变成"**从空目录自己搭出来**"。
本周结束时：一个**不抄旧项目、从零写**的最小 FastAPI 服务，能用 `/docs` 验证**创建 / 查询 / 修改 / 删除**四个接口。

## 带过来的缺口（本周重点盯）

- **#2 五层链路**：路由 / 参数 / 业务函数 / 存储 / 返回值 —— 你在**自己写的新代码里**要能逐层指出，别再只会背旧项目。

## 本周不做

- 不让 AI 生成完整函数或项目骨架（AI 只提示、指错、说下一步）。
- **不接数据库**（SQLite 留到第 3 周），本周存储先用内存（一个 dict 或 list）。
- 不碰 Docker / RAG / Agent。
- 不复制 `media-topic-assistant` 的代码；最多看它结构，代码自己敲。
- 不追旧周欠账。

## 每日安排

| 天 | 主任务 | 当天产出 |
|---|---|---|
| **Day 8** | 空目录建最小服务：建项目、装 `fastapi`+`uvicorn`、写第一个 `GET` 接口、跑起来看 `/docs` | 能跑的服务 + 一个能调的接口 |
| **Day 9** | 加 Pydantic 模型 + 内存存储（dict）；写「创建」`POST` + 「查全部」`GET` | 能新增、能列出 |
| **Day 10** | 「查单个」`GET /items/{id}`；找不到返回 **404** | 单个查询 + 404 |
| **Day 11** | 「修改」`PATCH`：只改客户端真传的字段；不存在 404 | 局部更新 |
| **Day 12** | 「删除」`DELETE`；不存在 404 | 四个接口齐 |
| **Day 13** | 用 `/docs` 把四个接口完整调一遍；补最小 pytest（可选）；**在自写代码上指出五层** | 验收证据 |
| **Day 14** | 检查点自测 5 题 + 周复盘（或休息） | 5 题 + 复盘 |

每天按 [[每日学习SOP]] 的节奏：先写代码（2.5h）→ 测试调试（1.5h）→ 脱稿讲 + 自测（1h）→ 投递（1h）。

## 检查点（本周"算过"的标准）

- [ ] 从**空目录**搭出可运行的 FastAPI 服务（不抄旧项目）
- [ ] 四个接口都在，且能用 `/docs` 调通
- [ ] 能在**自己的代码**里逐层指出：路由 / 参数校验 / 业务 / 存储 / 返回值（= 补上 #2）
- [ ] 错误输入返回明确状态码（`404` / `422`），不是 500
- [ ] 日志三栏本人写、5 题自测本人答

## 本周自测 5 题（不含答案）

1. 从空目录到"一个能跑的 API"，最少几步？每步在干什么？
2. 这周你的"存储"是什么？为什么这周先不接数据库？
3. Pydantic 模型在这四个接口里，各自挡住了什么坏输入？
4. `GET /items/{id}` 找不到记录时该返回什么？为什么不是 500？
5. 你新写的服务，和 `media-topic-assistant` 的请求链路，**哪里一样、哪里不一样**？
