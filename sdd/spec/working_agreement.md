# 协作规范（working agreement）

依据 sdd笔记.txt 的 SDD+TDD 方法论：

## 流程铁律

1. **Spec 先行**：所有开发先写规格，评审通过后再写代码。
2. **测试先行**：按规格先写失败测试（红），再实现到全绿（绿），最后重构。
3. **规格文档化**：规格统一存放于项目根目录的 `spec/` 文件夹，不只在对话里。
4. **一切可验证**：每条规格必须能转化为测试用例或类型约束
   （如"P99 延迟 ≤ 200ms"，而不是"性能不能太差"）。
5. **小步迭代**：每次只修改一个可独立验证的功能点，爆炸半径控制在单个端点内。

## 规格内容要求

- 数据模型、接口输入输出
- 校验规则、边界条件、错误返回
- **明确不做的事**（排除范围）
- 验证方法

## 三层验收（交付前必跑）

1. 静态校验：`python -m pyright`
2. 动态测试：`python -m pytest`
3. 人工复检：易用性与业务逻辑正确性

## 动态调整

规格不是一次性产物：实现中发现设计缺陷时，**先改规格再改代码**，保持
spec 与代码同步；测试用例随规格变化同步更新，已通过的用例沉淀为回归测试集。
