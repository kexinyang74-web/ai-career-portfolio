# Day 4：理解 Rust 与 SQLite 保存逻辑

## 今天要得到什么

看懂 `storage.rs` 如何验证数据、开启事务、写入当前记录与历史记录，并在任何一步失败时回滚。

## 只学项目里出现的 Rust

- `struct Note`：保存后返回的完整记录。
- `struct NoteInput`：前端送来的保存请求。
- `Option<i64>`：版本号可能存在，也可能为 `None`。
- `Result<T, String>`：成功返回 `T`，失败返回错误文字。
- `&str`：借用一段文字，不取得所有权。
- `&mut self`：方法需要可变地使用数据库连接。
- `?`：遇到错误立刻返回，否则取出成功值继续。

## 阅读顺序

1. `Note` 与 `NoteInput`：比较输入和输出字段。
2. `Database::open()`：打开数据库并创建 `notes`、`note_history`。
3. `Database::save()`：限制素材类型。
4. `validate_record()`：验证 ID、标题、正文、类型和版本。
5. `save_record()`：真正执行新增或更新。

## 新增与更新的差别

- `base_revision == None`：视为新记录，使用 `INSERT OR IGNORE`。
- `base_revision == Some(rev)`：视为更新，SQL 的 `WHERE` 同时匹配 ID 和版本号。
- 更新影响行数不是 1：说明记录不存在或已被别人更新，返回冲突错误。

## 为什么使用事务

一次保存包含多个动作：更新当前记录、复制到历史表、读取保存结果、提交。如果历史写入失败而当前记录已经永久更新，数据就会处于“当前版本存在、历史版本丢失”的半完成状态。

事务把这些动作绑在一起：全部成功才 `commit()`；中途任何 `?` 返回错误时，未提交事务自动回滚。
