# 学习日志模板

> **v2，2026-09-28 改版。** 旧版见本文末尾。
>
> 改版原因：旧模板字段多、每天重复，其中「一个我能讲清楚的原理」经常当天答不上来，
> 于是长期改由 AI 代填（Day 16–27 十余篇）。结果是回想环节被整个跳过，
> 直接造成「能做出项目，但脱离 AI 写不出代码」。

## 三条铁律

1. **必须本人写。** 三行也行，写得烂也行，错了也行。**AI 不代笔。**
2. **「答不上来」是合法答案，而且往往是最有价值的答案。**
   答不上来 = 今天没学会，这是信号不是失败。直接写「这块没懂」，它就变成明天的第一件事。
   **不要去问 AI 要答案再填进来**——那等于把报警器关掉，火还在烧。
3. **写完再交给 AI 批改**：挑错、补漏、指出哪里说得不准。批改另起一段，不覆盖你的原文。

## 格式（就这三栏）

```markdown
# YYYY-MM-DD DayN

## 1. 今天动手做了什么
- （做了什么、跑通了什么，一两句）

## 2. 卡在哪
- （没卡住就写「没卡」。卡住了写具体：哪个文件、哪一行、什么报错、怎么绕过去的）

## 3. 不看资料，现在能说出什么
- （合上资料凭记忆写。想不起来就写「想不起来」，不要去查了再回来填）
```

## 示例一：正常的一天

```markdown
# 2026-09-29 Day72

## 1. 今天动手做了什么
- 手写了一个工具的 Function Calling 循环，没用 LangGraph。跑通了天气查询那个例子。

## 2. 卡在哪
- 模型返回的 tool_calls 是个列表，我一开始当成单个对象用，报 AttributeError。
  改成取 [0] 之后通了，但为什么是列表还没想明白。

## 3. 不看资料，现在能说出什么
- Function Calling 不是模型自己去调函数，是模型告诉你「该调哪个函数、参数是什么」，
  真正执行的还是我自己的代码，执行完把结果再喂回去，模型才继续往下说。
```

## 示例二：没学会的一天（这样写完全合格）

```markdown
# 2026-09-30 Day73

## 1. 今天动手做了什么
- 跟着改了多工具调度那段代码，能跑，但基本是 AI 写的，我只改了变量名。

## 2. 卡在哪
- 全程都卡。不知道它怎么决定该调哪个工具的。

## 3. 不看资料，现在能说出什么
- 想不起来。这块没懂，明天先回头把单工具那个循环自己重写一遍再往下走。
```

第二篇日志比第一篇更有用——它准确指出了明天该干什么。
**连着三天写出第二种，说明进度太赶了，停下来补，不要往前冲。**

## 写作要求

- 每天 10 分钟以内。不追求长，追求真实。
- 代码要真的跑过，贴真实输出，不贴没验证的代码。
- 不要把 `.env` 里的密钥写进日志。
