# 简历项目描述模板（STAR 法）

项目描述是简历的灵魂。每个项目按"**背景 → 动作 → 结果**"写，突出技术点和量化数据。

## 公式

```text
【项目名称】（技术栈：xxx）
背景：面向 XX 行业/解决 XX 问题
动作：我负责/独立完成了 A、B、C（技术点要具体，覆盖目标 JD 关键词）
结果：带来了 XX 效果（量化：准确率/耗时/用户数/成本）
```

## 模板原文（复制后替换）

```text
XX 行业 AI 助手 ｜ Python · DeepSeek API · Prompt Engineering
为 XX 行业设计并实现对话式 AI 助手，解决 XX 场景下 XX 问题。
独立完成：调用大模型 API 实现多轮对话与流式输出；设计行业人设提示词体系
（角色设定/任务边界/输出格式）；实现对话历史管理、参数化配置与异常重试。
上线后内部演示获 XX 反馈，回答可用率达到 XX%。
```

```text
XX 行业知识库问答系统 ｜ Python · LangChain · Chroma · RAG
针对 XX 行业文档分散、人工查询耗时的问题，构建知识库问答系统。
独立完成：文档加载与多策略切分；Embedding 向量化与 Chroma 持久化；
检索-重排-引用流程；建立 30 条人工评测集持续调优。
回答可接受率从 XX% 提升至 XX%，且每条回答可溯源到原始文档。
```

```text
XX 行业日报自动生成 Agent ｜ Python · LangGraph · Function Calling
为 XX 岗位设计自动化信息收集 Agent，替代每日 XX 小时的人工整理。
独立完成：3 个自定义工具（信息抓取/文件读写/数据查询）；工具调用循环与
自我纠错机制；成本与 token 控制；自动生成带数据来源的行业日报。
连续运行稳定性 XX%，单次运行成本控制在 X 元以内。
```

## 量化数据的替代写法（没有真实数据时）

- 用"支持 X 个场景 / 覆盖 X 类文档 / 工具数 X 个"代替虚的百分比
- 用"从手动 2 小时缩短到 5 分钟"这类对比（要真实）
- 绝不编造"用户量/公司名/准确率"，面试追问会穿帮

## 投递前检查

- [ ] 项目段覆盖目标 JD 的 80% 关键词（Python、RAG、Agent、API、Docker 等）
- [ ] 每个项目有真实可演示的链接（GitHub / 在线地址 / 演示视频）
- [ ] 3 个项目放在简历靠前位置（教育背景后面）
- [ ] 每两周根据面试反馈更新一次
