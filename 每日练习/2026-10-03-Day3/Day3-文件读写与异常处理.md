# Day 3：文件读写与异常处理

日期：2026-10-03

## 今天的目标

把昨天写在代码里的素材列表改为从 JSON 文件读取，并分别处理正常文件、文件不存在、JSON 格式损坏三种情况。

今天不是重新写清洗功能。你要在现有代码上增加一层：

```text
JSON 文件 → 读取并解析 → Python 字符串列表 → 清洗 → 汇总 → 打印结果
```

## 为什么要做这一层

昨天的 `test_materials` 写死在代码里。每次更换素材都要修改程序，这不是真实项目常用的数据入口。

今天要把数据放进外部 JSON 文件（用文本保存结构化数据的文件），程序只负责读取。这样更换素材时只改数据文件，不改清洗逻辑。

## 三个需要认识的概念

### 1. 文件读取

程序需要知道文件路径、读取模式和编码。

- 文件路径：告诉程序去哪里找文件。
- 读取模式：今天只读取，不覆盖文件。
- `UTF-8`（中文文本常用编码）：避免中文读取成乱码。

### 2. JSON 解析

磁盘里保存的是文本。`json.load()`（读取 JSON 文件并转换成 Python 数据）执行成功后，程序才能得到列表。

需要区分：

- JSON 文件里的数组：文件格式中的数据。
- Python 中的 `list[str]`：程序运行时使用的字符串列表。

### 3. 异常处理

异常（程序无法按正常路径继续运行的情况）不能全部混成一句“出错了”。今天只区分：

- `FileNotFoundError`（指定路径找不到文件）。
- `json.JSONDecodeError`（文件存在，但内容不是合法 JSON）。

`try/except`（尝试执行并按错误类型分别处理）只包住可能出错的文件读取和 JSON 解析，不要包住整个程序。

新增一个专门读取素材的函数。开始写之前先在纸上或注释里回答：

1. 函数接收什么？
2. 函数成功时返回什么？

要求：

- 输入是文件路径。
- 成功时返回字符串列表。

### 第四步：连接原有流程

读取成功后，把得到的列表依次交给：

```text

```

删除或停用原来直接参与运行的硬编码 `test_materials`，但不要重写两个旧函数。

### 第五步：完成三次运行

每次只改变一个条件，并保存终端实际输出。

1. **正常文件**：`materials.json` 内容合法，程序打印清洗结果和汇总结果。
2. **文件不存在**：临时使用一个不存在的文件名，程序给出能看懂的提示，不出现整页报错。
3. **JSON 损坏**：临时删掉一个双引号、逗号或方括号，程序给出另一种提示，不和“文件不存在”混为一谈。

测试结束后，把 `materials.json` 恢复为合法内容。
