# 每日学习 SOP（每天照着走）

> 目的：把"每天该干嘛"固定成流程，省得每天重新想。原则来自三处：`求职向-后半程.md`（时间与主线）、协作标准（谁写谁批）、2026-10-08 定的日志记法（本子记问题）。
> 材料存放：当天任务与自测在 `学习安排\每日练习\YYYY-MM-DD-DayN\`（2026-10-08 起，临时学习已并入）。

## 一、一天的大块时间（按 `求职向-后半程.md`）

每天按 6 小时算，四块：

| 时间块 | 干什么 |
|---|---|
| **大头**（约 2.5h） | **本人写代码**。最难的放上午，状态最好的时候 |
| 次块（约 1.5h） | 测试、调试、读日志、改旧代码 |
| 一小块（约 1h） | **脱稿讲**今天做的 + **做自测** |
| 一小块（约 1h） | 看 JD、投递（每周 3–5 份，并行，不等学完） |

写代码时段里，AI **只给提示、指错、说下一步**，不生成完整功能。

## 二、每天的步骤（按顺序）

### 第 0 步 · 开一天（我说"开始下一天"时）
1. 打开当天任务文件 `DayN-xxx.md`——它就是今天的剧本，写了做什么、验收标准、卡住怎么问。
2. 确认起点干净：需要时跑 `git status`；要做改动实验的先跑一遍**基线测试**，记下通过数。
3. **纸本子摊开**，写一句今天的目标。

### 第 1 步 · 边做边记（主体）
1. 照任务文件一步步做。**代码自己写。**
2. 每个练习/改动，**先写预测，再运行**（会报什么、哪一层、哪个测试红）。
3. **卡住时**：先写自己的猜测 → 贴报错原文那几行 + 相关代码 → 只问"错在哪 / 下一步"，不要完整答案。
4. **每卡一次、每想通一处，就在本子上写一个"问题"**（不写答案）。
5. 报错原文**原样**抄进本子。

### 第 2 步 · 验证闭环
- 改完跑测试/命令，把结果和预测对照。
- 差异记下来：漏了 / 记岔了 / 顺序错（遮盖重写、改坏都这么记）。

### 第 3 步 · 自测（收尾，约 10–15 分钟）
- 打开 `DayN-自测5题.md`，**合上资料，本人作答**。不知道就写"不知道"。
- 交给我批改（✅/⚠️ + 补漏）。

### 第 4 步 · 回想日志（收尾，约 10 分钟）
三栏模板：
1. **今天动手做了什么** → 照本子上的**事实**填。
2. **卡在哪** → 照本子填（哪个文件、哪一行、什么报错）。
3. **不看资料，现在能说出什么** → **把本子上的"问题"当回想题，合上一切、凭脑子逐个答**；答不出就写"想不起来"。
- 第 3 栏**答不出的问题，圈起来 = 明天的第一件事**。

### 第 5 步 · 批改与反馈
- 我批改自测和日志：挑错补漏，**不覆盖你的原文**。
- 新暴露的缺口记进记忆，作为后面复习点。

### 第 6 步 · 投递（并行）
- 看 JD、定向投（每次 3–5 份/周的量，不为凑数放宽硬线）。

## 三、每天结束的自检

- [ ] 今天的目标写了
- [ ] 每个卡点都变成了本子上的一个"问题"
- [ ] 自测是**本人、脱稿**作答
- [ ] 日志第 3 栏是**回想**出来的，不是照本子抄的
- [ ] 答不出的问题 → 已列为明天的第一件事
- [ ] 改动实验后，项目复原、测试回到基线

## 四、红线（破了就等于白练）

1. **AI 不代写代码、不代填日志、自测不给答案。** 我会主动拦。
2. **想不起来就写"想不起来"**，别去查了再回来填。
3. 遮盖重写、故意改坏时：**关掉原版、关掉编辑器补全**。
4. 中断之后**不补课**，落下的勾销，从当天继续。

## 五、谁干什么（分工）

| 我（AI） | 你（本人） |
|---|---|
| 开一天时建任务文件 + 自测题 | 照任务文件写代码 |
| 讲解、给提示、指错 | 先写预测再运行 |
| 批改自测 / 日志（✅⚠️、补漏） | 自测作答、写日志、做回想 |
| 出追问题、追旧缺口 | 本子上记"问题" |
| 更新记忆与进度（以你实际完成为准） | 自己跑 `git status/diff/log` 验收 |

提交、推送只在你说"提交并推送"时才做。
