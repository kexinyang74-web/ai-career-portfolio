## 第 1 题

**`uvicorn main:app --reload` 里，`main` 和 `app` 分别指什么？**

你的答案：
> main 是文件夹的名字。
> app 是文件中的一个变量，app=fastapi.FastAPI()

判定：⚠️ 一半对。

批改：
- **`app` ✅ 对**：`main.py` 里那个变量（FastAPI 实例），没错。
- **`main` ❌ 错**：不是文件夹名，是**模块名**——也就是 `main.py` 这个**文件**。`main:app` 的冒号前是"**哪个模块（文件）**"，后面是"**里面的哪个变量**"。
- 一句话记住：**`main:app` = 文件 `main.py` 里的变量 `app`。** 文件夹名不起作用。

## 第 2 题

**从空目录到"一个能跑的 API"，最少有哪几步？**

你的答案：
> 一个最小的 fast API 框架是先 import，引入一个工具或者是方法，然后再命名你要引用的变量名，然后再在装饰路由，然后再定义函数，最后输出。5 步吧

判定：⚠️ 只答了"写代码"这一段。

批改：
- 你列的顺序（import → 建实例 → 装饰路由 → 定义函数 → return）**在文件内部是对的**，但题目是"**从空目录**"——你漏掉了两头各一步：
  1. **建目录 + 建虚拟环境 + 装包**（`python -m venv .venv`、`pip install fastapi "uvicorn[standard]"`）——这是"空目录"能起步的前提；
  2. **启动 + 验证**（`uvicorn main:app --reload`，浏览器开 `/docs` 调通）。
- 所以更完整是 **4 大步**：
  1. 建环境：目录 + `.venv` + 装 `fastapi`/`uvicorn`；
  2. 写 `main.py`：`import` → `app = FastAPI()` → `@app.get(...)` + 函数；
  3. 启动：`uvicorn main:app --reload`；
  4. 验证：`/docs` 里调通。
- 一处措辞：不是"命名变量名"，是**创建 FastAPI 实例并赋值给变量**。

## 第 3 题

**`@app.get("/health")` 这行，和它下面的函数，谁先谁后？请求进来时发生了什么？**

你的答案：
> `@app.get("/health")`先，函数后。请求进来时，好像是根据 `@app.get("/health")` 这一行……判断能不能符合要求，如果符合要求，就执行下面的函数，相当于一个是装饰器还是引导的作用。这块有点模糊

判定：⚠️ 机制方向对，缺"什么时候登记"这一层。

批改：你自己标了"模糊"，说明你嗅到了没吃透的地方。补上两段时间线：
- **代码书写**：装饰器行在上，函数定义在下——你说的"谁先谁后"就指这个，✅。
- **执行时机**（关键）：
  1. **程序启动、加载 `main.py` 那一刻**，装饰器**立刻**把下面的函数**登记进路由表**（"`/health` 这个方法+路径 → 这个函数"）。此时请求还没来。
  2. **请求进来时**，FastAPI 拿 方法 + 路径 去路由表里**匹配**；命中就**调用登记过的那个函数**。
- 所以你说的"通过 `/health` 判断符不符合 → 执行函数"**是对的**，只差一句：**登记发生在启动时，不是请求时**。装饰器的作用就是"**登记 + 绑定**"，不是"引导"。

## 第 4 题

**`/docs` 页面你一行都没写，它是从哪来的？**

你的答案：
> 什么叫我一行都没写？它是从哪来的？是代码里面一行都没写啊？我猜测是跟我引用的 fastapi 有关吧

判定：⚠️ 方向对，没说清机制。（另外：这题问的是"这个页面哪来的"，不是问你代码里写没写，题目表述让你误解了，正常。）

批改：
- 你猜"跟引用的 fastapi 有关"——**方向对**：`/docs` 是 FastAPI **自动送的**。
- 机制：你注册的**每条路由 + 函数的类型信息**，FastAPI 会在启动时**自动生成一份 `OpenAPI` 文档数据**，并且**内置挂载**好两个页面：
  - `/docs` → Swagger UI（你今天用的那个）
  - `/redoc` → ReDoc
- 所以你确实**一行都没写**：页面、文档、交互全靠框架从你的代码里**自动推导**。这也是 FastAPI 相对 Flask 的一个卖点。

## 第 5 题

**你今天这个接口，五层里，有哪几层、缺哪几层？**

你的答案：
> 有路由，有参数，有返回值，没有业务和存储

判定：⚠️ 2 对、1 错、1 需商榷。

批改：拿 `main.py` 逐层对：

| 层 | 今天有没有 | 在哪 |
|---|---|---|
| 路由 | ✅ 有（你对） | `@app.get("/health")` |
| 参数 | ❌ **没有**（你答错） | `/health` 无参，函数也没入参 |
| 业务 | ⚠️ **有，只是极薄** | 函数体 `return {"status":"ok"}` —— 这就是"业务"这一层 |
| 存储 | ✅ 没有（你对） | 没有读写任何数据 |
| 返回值 | ✅ 有（你对） | `return {"status":"ok"}`，被转成 JSON |

- **"有参数"是误判**：你今天这个接口**没有任何参数**。"参数"这一层要等 Day 9/10 出现 `POST` 请求体、`/items/{id}` 路径参数时才会有。
- **"没有业务"要收回**：任务里问的就是"业务：函数体里做了什么"。今天它**薄**（只是造一个固定字典），但"函数体就是业务层"——不能说没有。等 Day 9 加了存储和真正逻辑，这一层会变厚。
