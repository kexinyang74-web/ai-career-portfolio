## 第 1 题：列表 vs 元组（检查点 ②）

说说列表（list）和元组（tuple）的**两个**区别，并各举一个"什么时候用哪个"的场景。

你的答案：
第一个区别是是否可以修改它。列表可以修改，元组没办法修改
第二个区别是能否作为字典的键，它列表不能作为字典的键，元组可以作为字典的键
一个应用场景就是用二维坐标索引地图数据的时候用元组
```python
map_data = {(10, 20): "宝箱"}
```

## 第 2 题：字典 vs 集合（检查点 ②）

字典（dict）和集合（set）都是"带大括号"的容器。它们**本质区别**是什么？什么时候用字典、什么时候用集合？（提示：字典存的是"键→值"，集合存的是"有哪些"）

你的答案：
字典和集合的本质区别是，字典它可以保存键和值的对应关系，然后集合的话只保存有哪些元素，不附带对应的值
对于什么时候用字典，什么时候用集合，用一句话来讲就是字典回答它对应什么，集合回答它在不在。就是当你要不仅要判断某个键是否存在，还要找到它的相关信息，使用字典。如果你只关心元素是否存在，需要去重，或者要做交集遍历运算，使用集合

## 第 3 题：try/except（检查点 ③）

为什么要用 `try/except`？为什么 `except:`（裸捕获，不写错误类型）是坏习惯？

你的答案：
`try/except` 用来处理**运行时可能发生、但程序可以合理应对的异常**，避免程序直接崩溃。
裸 `except:` 是坏习惯，因为它会捕获几乎所有异常：
- **掩盖程序错误**
    
    即使代码里出现拼写错误、变量不存在等 bug，也会被悄悄吞掉，让你误以为程序正常运行。
    
- **无法针对不同错误正确处理**
    
    文件不存在、网络中断、数据格式错误，解决办法并不一样。全部混在一起无法精确处理。
    
- **会拦截程序退出信号**
    
    裸 `except:` 连 `KeyboardInterrupt`（用户按 `Ctrl+C`）和 `SystemExit` 等异常也可能捕获，导致程序难以正常停止。
## 第 4 题：logging vs print（检查点 ③）

用一句话+一个例子说明：什么情况下 `print` 搞不定、必须用 `logging`？（提示：排查一个跑了 2 小时才出错的程序）

你的答案：
**一句话：**当程序长时间运行、需要保留“何时、在哪、因为什么出错”的记录以便事后排查时，必须用 `logging`，因为 `print` 通常只临时显示信息。
```python
import logging

logging.basicConfig(
    filename="app.log",
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s"
)

try:
    run_two_hour_task()
except Exception:
    logging.exception("任务执行失败")  # 自动记录时间、错误和调用栈
```
## 第 5 题：综合实战（检查点 ①）

这是"独立写出 100 行脚本"的迷你版。请**不查资料**写出一个函数：

> 输入一个文件名列表 `files = ["a.txt", "b.jpg", "c.txt", "d.pdf"]`，用 `pathlib` 把 `.txt` 文件重命名成 `1.txt`、`2.txt`……（加序号，`enumerate` 从 1 开始），其他后缀不动。

要求：函数命名 `rename_txt(files)`，返回改名后的文件名列表。写完可以本地跑一下验证。

你的答案：
```python
from pathlib import Path


def rename_txt(files):
    renamed_files = list(files)

    txt_files = (
        (index, Path(filename))
        for index, filename in enumerate(files)
        if Path(filename).suffix == ".txt"
    )

    for number, (index, path) in enumerate(txt_files, start=1):
        new_path = path.with_name(f"{number}.txt")
        path.rename(new_path)
        renamed_files[index] = str(new_path)

    return renamed_files
```
