## 一、核心要点（一页速记）

- `git status` = 体检报告：当前分支、本地和远程差几个提交、有没有未暂存（modified）或未跟踪（untracked）的改动
- `git log --oneline` = 存档点清单：每行一个提交（编号 + 说明），最新在顶；`HEAD` = 当前位置，`origin/main` = 远程位置
- `git diff` = 精确到行的改动：`-` 旧内容、`+` 新内容、`@@` 改动位置
- 分支 = 指向某个提交的指针；clone = 完整复制一份仓库；commit 只存本地，push 才上传
- 口诀：**status 看全局，diff 看细节，log 看历史**

## 三、重点再讲（4 处修正 + 2 题补讲）

1. **`@@` 是"改动在哪、范围多大"，不是"改了什么"**：`@@ -旧行数 +新行数 @@` 帮你定位，改动内容看它下面带 `+` / `-` 的行
2. **"up to date with origin/main" ≠ 没有未提交改动**：前者只表示和远程提交同步，未提交改动是另一回事，两个可以同时存在（就像 push 完还有 .obsidian 的 modified）
3. **删分支 ≠ 删提交**：分支是指针，删的是指针；提交还在历史里，能找回
4. **git log 看历史，不看时间**：`--oneline` 每行是"编号 + 说明"，不显示时间戳
5. **"领先几个"怎么数**：`origin/main` 停在那一行是远程已有的提交，**它上面有几行 = 本地领先几个提交**；ahead 的单位是提交（commit），不是文档
6. **git log 为什么最新在最上**：默认按时间倒序输出（新 → 旧），这是设计好的显示顺序，方便一眼看到最新状态

## 四、复习检查单（以后每次提交前用）

1. `git status` → 有没有未提交/未推送的改动？
2. `git diff` → 具体改了什么？有没有误提交敏感文件？
3. `git log --oneline` → 新增了哪个存档点？
4. 确认无误后让 AI 提交并推送；结束后再看一眼 status：**up to date + 没有未提交改动 = 干净收工**
