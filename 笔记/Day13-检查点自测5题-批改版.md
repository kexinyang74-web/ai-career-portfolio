## 第 1 题：列表 vs 元组 ✅

- 可修改性：列表可变、元组不可变 ✅
- **字典键**：列表不能当键、元组可以 ✅（进阶知识点：涉及"可哈希 hashable"，元组不可变所以可哈希）
- 场景：二维坐标当元组键 `{(10, 20): "宝箱"}` ✅

**补充**：为什么元组能当键？——字典的键必须是**可哈希**的（能算出固定身份），而"可哈希"要求值**不可变**。元组内容确定后不能改，身份永远稳定；列表能改，身份会变，不能当键。这个"可变 ↔ 不可变 ↔ 可哈希"的关系是 Python 的核心概念，第 3 周讲 class 时你会再见它。

## 第 2 题：字典 vs 集合 ✅

- 本质区别：字典存"键→值"对应关系，集合只存"有哪些元素" ✅
- 场景总结：**字典回答"对应什么"，集合回答"在不在"** ✅
- 集合用途：去重、交集/并集/差集运算 ✅

**补充**：面试标准答法就是你说的这两句——字典是"查表"，集合是"名单"。判断标准：**"我要不要拿回一个关联的值？"要→字典；只是判断存在/去重→集合。**

## 第 3 题：try/except ✅（超出要求）

- 为什么用：处理**运行时可能发生、程序能合理应对**的异常，避免崩溃 ✅
- 裸 except 坏处 1：掩盖 bug（拼写错、变量不存在也被吞掉）✅
- 裸 except 坏处 2：无法针对不同错误精确处理 ✅
- 裸 except 坏处 3：**会拦截 KeyboardInterrupt（Ctrl+C）和 SystemExit** ✅（深度知识点）

**补充**：第三条是很多人不知道的——`except:` 连"用户按 Ctrl+C 中断程序"都会被接住，程序想停都停不下来。正确写法永远带错误类型：`except FileNotFoundError:`、`except (ValueError, TypeError):`（多个错误用括号）。

## 第 4 题：logging vs print ✅

- 一句话：长时间运行的程序要保留"何时/在哪/为什么出错"的记录，print 只临时显示 ✅
- 用了 `logging.exception()`（自动记录时间、错误、调用栈）✅ 加分写法

**补充**：`logging.exception` 只能在 except 块里用，它等价于 `logging.error(msg, exc_info=True)`——把完整调用栈写进日志，事后排查定位到行号。这是"生产级"习惯。

## 第 5 题：综合实战 ✅（功能正确，超纲写法）

**思路**：找 txt → 按原顺序编号 → 重命名 → 更新返回列表。完整闭环，可以直接跑。

**亮点**：
- `enumerate(files)` 保留**原索引**，重命名后精确更新返回列表的对应位置 ✅
- 生成器表达式 `(...)` 惰性求值，大列表也不占内存 ✅（超纲但正确）
- `path.with_name()` 换名字不换位置 ✅

**优化点（不影响正确性）**：`Path(filename)` 构造了两次，可以合并：

```python
from pathlib import Path

def rename_txt(files):
    renamed_files = list(files)
    txt_entries = ((i, Path(f)) for i, f in enumerate(files) if Path(f).suffix == ".txt")
    for number, (index, path) in enumerate(txt_entries, start=1):
        new_path = path.with_name(f"{number}.txt")
        path.rename(new_path)
        renamed_files[index] = str(new_path)
    return renamed_files
```
