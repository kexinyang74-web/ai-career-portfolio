## 第 1 题：为什么要分层（检查点 ①）

**你的答案：**
1. 因为不动文件更方便修改，把读取参数和清洗参数放在一起会职责混乱。
2. 再+json又需要重新修改清洗参数，理想情况是再+一层转换参数在清洗参数外。就像excel那样

**批改：⚠️**

- 第 2 点 **对**：加 JSON 不该改清洗；该在清洗外面再加一层转换。这就是 loader 的存在理由。
- 第 1 点方向对（职责分开），但「读取参数 / 清洗参数」用词偏了——分开的是**两层代码**（读文件 vs 洗 dict），不是两套「参数」。
- 缺了这周最硬的一条：**清洗不碰文件 = 纯函数 = 好测**。不 `open` 文件，测试才能直接塞字符串、看返回值，不用造一堆临时 csv/xlsx。

补一句（自己写进日志也行）：清洗只认 `{列名: 值}`，所以 CSV/Excel/JSON 只改 loader，测试只测 cleaner。

## 第 2 题：环境复现（检查点 ②）

**你的答案：** 三步 `venv` → `Activate.ps1` + `pip install -r` → `pytest`；直接依赖 vs 间接依赖（pytest→pluggy/iniconfig，openpyxl→et-xmlfile）。

## 第 3 题：测试替你盯场（检查点 ③）

**你的答案：**
1. 测试在运行时会出现红色，然后给我定位哪里出错
2. assert  %Y/%m/%d、%Y-%m-%d、%Y.%m.%d == YYYY-MM-DD
3. E行，什么错误。 where行，出现在哪里

**批改：⚠️**

- 「变红 + 能定位」对，但太空——任何失败都会红。
- 第 2 点把 **实现手段** 写成了 **断言**。测试钉死的是**具体例子**，例如：`"2024/1/5"` → `"2024-01-05"`，`"2024/2/30"` → `None`。它不会去 assert 三个格式字符串等于 `YYYY-MM-DD`。
- E / where：**接近**。更准一点：
  - **E 行**：实际值 vs 期望值（你得到了什么、测试要什么）
  - **where 行**：失败发生在哪一条 `assert`

改坏 `clean_date` 之后：跑 pytest → 红 → 先读 E（比如实际 `None`、期望 `'2024-01-05'`）→ 再看 where 定位到哪条测试。

## 第 4 题：调试器 vs print（检查点 ④）

**你的答案：** 断点打在 `sum = score`；看 sum 的变化；不改代码结构、不会忘删 print。

**批改：✅**

断点位置对（就是那行赋值）。不改源码、不会留垃圾 print，这就是调试器相对 print 的主要好处。

可记一句现象（你 Day 24 亲眼见过）：sum **应该** 0→80→170→270，**实际** 若写成覆盖则是 80→90→100。确认「没累加」靠的是这个序列，不单是「看了 sum」。

## 第 5 题：PowerShell + 编码（检查点 ⑤）

**你的答案：** 数据量大，不加测试容易一出错错一大堆；不带 `-Encoding UTF8` 会乱码。

**批改：⚠️**

- dry-run：怕批量出错要改回来，方向对。更关键的一句是 **改名/覆盖不可逆**——就算只有 4 个文件，先预览也值得。数据量大是加重因素，不是唯一原因。
- 乱码：**现象对，原因没写完**。PowerShell 5.1 里 `Set-Content` 默认常按系统 ANSI（中文 Windows 多为 GBK）写盘，VS Code 按 UTF-8 打开 → 才乱码。所以写中文要显式 `-Encoding UTF8`（对照 Day 20/26 写 CSV 用 `utf-8-sig`）。
