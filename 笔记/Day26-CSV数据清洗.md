# Day 26 CSV 数据清洗(小脚本 3 前半)

> 第 4 周第 5 天。核心:脏 CSV → 清洗(去重/去空/修格式)→ 干净 CSV + 统计报告。配套:projects/python-practice/day26/(Day 27 补 Excel 部分)。Day 26 写的两个清洗函数在 cleaner.py(用户本人实现)。

## 一、为什么数据要清洗

| 脏的来源 | 例子 |
|---|---|
| 人工录入 | 前后空格(" 华东 ")、漏填、错别字 |
| 多系统导出拼接 | 格式不统一:日期 `2024/1/5` vs `2024.1.5`;金额 `¥1,200` vs `800元` |
| 操作失误 | 整行重复、空行、`abc` 混进金额列 |
| 看着像日期不是日期 | `2024/2/30`(2 月没有 30 号) |

原则:**垃圾进,垃圾出(garbage in, garbage out)**——AI 训练/API 输入都要干净数据。

## 二、清洗流水线设计

```
原始行 → 去首尾空格 → 修格式(金额/日期/数量)→ 没救就丢 → 去重 → 干净行
```

三件套架构:cleaner.py(纯函数库)+ main.py(流程)+ test_cleaner.py(测试)。

## 三、纯函数设计(为什么能测)

**纯函数 = 同样的输入永远同样的输出,不碰文件、不打印**。所以:
- 单值解析:clean_money / clean_date / parse_int(字符串 → 修好的值或 None)
- 行级清洗:清洗一行(一行 → 修好的 dict 或 None)
- 多行:去重(整行相同留首个)/ 按区域汇总

用户实现的 clean_money 思路:`replace` 删掉 ¥、,、元 → `float()`;转不了 → None。
clean_date 思路:`strptime(text, 格式)` 逐个试 %Y/%m/%d、%Y-%m-%d、%Y.%m.%d → 成功 `strftime('%Y-%m-%d')` 统一;全失败(含 2024/2/30)→ None。

## 五、今天的坑

1. **pass 残留**:`pass` 是"占位空语句",不是函数结束标记——写在它后面的代码照样执行(所以功能对),但留着它=告诉读者"这里没写"。**实现完成后删掉 pass**。
2. **报告对不上手算?先别怀疑程序**:错误在手算——把张伟 1/10 的订单当重复删了。**重复 = 整行完全相同,日期不同是另一张单**。对账方法:**拿程序输出的干净 CSV 逐行加**(8 行),别拿原始脏数据心算。
3. csv 模块的 DictReader **自动跳过空行** → 原始计数不含空行(不是 bug)。

## 六、工程细节

- 读脏 CSV、写干净 CSV 都用 `encoding="utf-8-sig"` → Excel 打开不乱码(Day 20)
- csv.DictReader → 每行是 {列名: 值} 的 dict,列名访问可读性最好
- CSV 里含逗号的字段必须加引号:`"¥1,200"`(否则被当分隔符拆列)
- 报告格式化:`{total:,.2f}` → 千分位 ¥8,451.00
