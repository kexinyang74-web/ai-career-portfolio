# Day 24 VS Code / Cursor 调试器

> 第 4 周第 3 天。核心：断点/单步/变量监视，用调试器定位一个"不报错但算错"的逻辑 bug。配套练习：projects/python-practice/day24/01_debug_me.py。

## 一、为什么用调试器？（print 大法的天花板）

| print 大法的痛 | 例子 |
|---|---|
| 要改代码才能看 | 打印完忘了删，代码里全是 print |
| 只看结果看不到过程 | 循环第 3 轮变量是多少？print 得自己加条件 |
| 崩溃前最后几步看不到 | 报错前发生了什么？print 来不及 |

调试器：**代码不改一行**，让它边走边停、逐帧回放、随时看任何变量。

## 二、核心操作（键盘为主）

| 操作 | 快捷键 | 干什么 | 比喻 |
|---|---|---|---|
| 打断点 | 点行号左侧（红点） | 程序跑到这行暂停 | 跑道上设暂停线 |
| 启动调试 | F5 | 开始调试当前文件 | 发令枪 |
| 单步跳过 | F10 | 执行一行，不进入函数 | 跨过水坑 |
| 单步进入 | F11 | 进入函数内部一步步走 | 跳进坑里看 |
| 继续 | F5（调试中） | 跑到下一个断点 | 继续放行 |

左侧面板：
- **变量**：所有变量的实时值（核心！）
- **监视**：盯特定表达式
- **调用堆栈**：当前在第几层函数

## 三、今天的实战案例（Bug 定位全流程）

**症状**：01_debug_me.py 不报错，但输出 33.33（期望 90.0）——**逻辑错**（能跑但算错），最难查的类型。

**Bug 代码**：`sum = score`（应该是 `sum += score`）

**调试过程**（断点 → 单步 → 变量面板）：
- 断点打在 `sum = score` 行
- F10 单步三轮，盯变量面板
- 期望 sum 累加：80 → 170 → 270
- 实际 sum 覆盖：80 → 90 → 100（被每轮 score 冲掉）
- **结论：= 是覆盖，+= 才是累加**（`sum += score` 等价于 `sum = sum + score`）
- 修复 → 重跑 → 90.0 ✅

**调试七步流程（记下来）**：断点 → 启动（F5）→ 单步（F10）→ 看变量 → 定位 → 修复 → 验证

## 四、F5 弹窗问题（今天实测）

**症状**：按 F5 弹"选择配置"、按蓝色"Run and Debug"没反应。

**两个根因与解决**：
1. **没选 Python 解释器**（Cursor 装扩展后第一次要用）：Ctrl+Shift+P → "Python: 选择解释器" → 选 venv 或全局 python
   - 解释器列表里的每个 python = 一个环境（联系 Day 22 venv：选 .venv = 在抽屉里跑）
   - day24 没建 .venv，用全局跑完全没问题（练习文件零第三方依赖）
2. **没有 launch.json**（调试配置文件）：Ctrl+Shift+D → "创建 launch.json" → 选 Python Debugger → 生成后 F5 永远调试当前文件，不再弹窗。以后每个新项目都会遇到一次，建了就是一劳永逸

## 五、一句话总结

**调试器 = 程序的慢动作回放**：print 是"事后看结果"，调试器是"现场看过程"。遇到"不报错但结果错"的 bug，别猜，打断点单步看变量——**变量面板会告诉你真相**。

## 六、操作速查

```text
点行号左侧       打断点（红点）
F5               启动 / 继续到下一断点
F10              单步跳过（不进函数）
F11              单步进入（进函数）
Shift+F11        单步跳出函数
Ctrl+Shift+P     Python: 选择解释器
Ctrl+Shift+D     打开运行和调试面板
```
