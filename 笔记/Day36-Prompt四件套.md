# Day 36 Prompt 四件套（第 6 周第 1 天）

> 第 5 周管「怎么把请求发出去」。今天管 **messages 里写什么**。对照你已有的 `projects/project-1-ai-assistant/system_prompt.md`。

## 一、四件套（先记名字）

| 件          | 管什么          | 在你现有人设里大概对应            |
| ---------- | ------------ | ---------------------- |
| **角色**     | 你是谁、服务谁      | 「选题与脚本助手」+ 创作者人设那段     |
| **任务**     | 这次要产出什么      | 「10 个选题 + 3 个开头」/ 口播三段 |
| **约束（边界）** | 不准干什么、不确定怎么说 | 「只帮 B站 创作」「不编造播放量」     |
| **输出格式**   | 结果长什么样，方便你用  | 编号列表、钩子/中段/CTA         |

糊指令只有任务的一半（「帮我想选题」），模型就自由发挥，容易变回空话或串到别的行业。四件套不是把 prompt 写长，是把这四格填满。

`system` 适合放稳定的角色+边界+默认格式；`user` 适合放这一次的任务（赛道、条数、截止日期）。人设反复变就该改 system；只换选题关键词就改 user。

## 二、今天实验（必须你跑）

在项目一目录、venv 已激活：

**A. 糊的 user（只有半句任务）**

```powershell
python main.py "帮我想几个选题"
```

**B. 带四件套的 user**（角色已在 system 里，这里补任务+约束+格式）

```powershell
python main.py "任务：给「转行学编程」赛道 5 个选题。约束：必须能拍成生活记录+口播，不要鸡汤标题。格式：每条一行，标题 — 一句话钩子。"
```

把两次回复的差异写进日志（哪次更能用、哪次像模板）。不要把密钥贴出来。

可选：打开 `system_prompt.md`，用笔标出四段各属四件套的哪一件。

## 三、和 temperature 的分工

Prompt 决定「规则」；temperature 决定「下一个字抽多散」。规则没写清，拧温度救不了。今天先改字，不改 `.env` 里的温度。
