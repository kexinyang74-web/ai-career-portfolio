## 第 3 题：B 和 C

**批改：✅**（用户更正后）5→3 **不是** few-shot 的功劳，是你在 C 的任务里把条数改成了 3。上一版批改把条数算进例子，归因错了。

拆开两颗螺丝：

- **条数**：B 写 5、C 写 3 → 输出条数跟着任务走；更短首先是因为条数少。
- **few-shot**：C 多的是「格式与例子完全一致 + 一条样例」。能认到它头上的，主要是 **形状**（更贴那一行标题/钩子、少了一段「为什么适合你」），不是选题更好。

所以你说内容/可用性「变化不大」说得通；「更短」不要写成例子的效果。若 B 和 C 都写 3 条、只多例子，才能单独看 few-shot。

## 第 4 题：system 默认

**批改：✅** A 被「默认 10 选题 + 3 开头」带走，证据就是分类小作文和 3 个爆款开头，和 `system_prompt.md` 第 12 行对得上。

补一刀：B **没有**再出 10+3，但仍被另一句默认带走——「先给可用结果，再补一句为什么适合这个人设」。所以限制条数/格式能压住 10+3，压不住「再补一句」。C 用例子把形状钉死后，这句补白也弱了。

## 第 5 题：设计决策

**批改：⚠️** 留 B 可以；理由没用上四件套的词，而且和「不知道格式」拧着。

- **任务 / 约束 / 格式** 能用自己的话写清时，B 就够当日常模板。
- **格式你说不清、但手里有一条好输出** 时，才用 C 的 few-shot 让模型抄形状。

「一开始不知道想要的格式」更像 **先跑一版 B 看形态 → 把好看的那条收成例子再写成 C**，不是「所以永远只用 B」。
