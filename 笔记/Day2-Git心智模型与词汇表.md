# Day 2 · Git 心智模型与词汇表

> 日期：2026-08-19 ｜ 对应任务 3（心智模型）+ 任务 5（关键词汇）

## 一、一句话理解

Git 是"存档系统"：把文件夹的每次改动做成存档点，随时能回到任意存档，还能同步到 GitHub。

## 二、三个区域

```text
工作区 ── git add ──> 暂存区 ── git commit ──> 版本库
（编辑中的文件）     （待提交清单）          （永久存档）
```

- 工作区：你正在编辑的文件夹
- 暂存区：你选好"这次要存哪些改动"的清单
- 版本库：真正的存档柜（.git 里的历史）

## 三、本地与远程

- 本地仓库 = 电脑上的存档；远程仓库 = GitHub 上的存档（备份 + 给面试官看）
- `push` = 本地存档上传到 GitHub；`pull` = 把 GitHub 的存档拉回本地
- 记住：**commit 只存在本地，push 才上传**。看到 "ahead by N commits" 就是"本地有 N 条还没上传"

## 四、分支

- `main` = 主时间线
- 分支 = 平行时间线（随便改不破坏主线）
- `merge` = 把分支合并回主线

## 六、自测 5 题（答完 Day 2 检查点打勾）

1. 三个区域按什么顺序流转？`git add` 和 `git commit` 各干什么？
	1. 先回答第一个问题，三个区域按什么顺序流转？他可能是按工作区，然后流转到暂存区。暂存区再流转到那个版本库（永久存储区）。
	2. 然后第二个问题，这个git add它的作用就是把你工作区内容上传到暂存区，这是我的理解;然后 git commit它的作用就是把你暂存区的内容上传到版本库，也就是本地储存。
2. `git commit` 和 `git push` 有什么区别？
	1. 这两个区别是不是在于，前者是上传到本地，然后后者他是把本地里面的修改上传到远程仓库云端，也就是
3. 分支是什么？`merge` 干什么？
	1. 分支好像就是就是一个跟备份类似的一个东西，就是相当于把你这个工作状态分出来一份儿完全一样的。但是，你新分出来的这个修改的话，不会影响主线的内容
	2. merge是不是就是把就是主线分出来的内容跟主线合并这一部分，我感觉有点儿混乱，只是字面意思上的理解
4. 冲突什么时候发生？
	1. 冲突就是你可能在合并的时候会有一些不一样的内容，然后他就会问你批不批准之类的
5. Obsidian Git 插件自动帮你执行了哪三步？
	1. 通过我的理解，它这个插件可能自动帮我执行了commit，还有push，可能还有pull，但是我暂时还没有看到pull的这个结果
