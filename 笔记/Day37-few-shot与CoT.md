# Day 37 少样本 few-shot + 思维链 CoT（第 6 周第 2 天）

> 昨天四件套管「格子填满」。今天两件加分道具：**给例子**（few-shot）、**先想步骤再给结果**（CoT）。仍用项目一 `python main.py "..."`，密钥只在 `.env`。

## 一、few-shot（少样本）

模型不只听规则，也**模仿你给的样子**。

- **零样本**：只说规则，不给成品例子（昨天的结构指令就是）。
- **少样本**：规则 + 1～3 条「输入 → 你想要的输出」。标题风格、钩子长度、能不能用脏话，例子比形容词管用。

例子要和目标任务**同格式**。给一条「标题 — 钩子」的样例，再要求 5 条，模型更容易一行一条，而不是又展开成小作文。

**注意**：例子会占 token（上下文更贵）；例子质量差，模型会学坏。

## 二、CoT（思维链）

CoT = 允许或要求模型 **先分步想，再给最终清单**。适合：要筛选符不符合人设、要避开鸡汤、要解释「为什么这条能拍」。

代价：更长、更费 token；有时步骤对、清单仍虚。要「只给清单、不要分析」时就**不要**开 CoT。

和四件套的关系：CoT 是任务怎么执行的过程；格式仍要写清最终长什么样（否则步骤写了一堆，你还是不好用）。

## 三、今天实验（三次，记下差异）

项目一目录、venv 激活后：

**1. 零样本（对照昨天）** 若昨天结构那次还在印象里，可跳过，直接做 2、3。

**2. 少样本**（把样例嵌进 user；system 人设不用改）

```powershell
python main.py "任务：转行学编程，再给 3 个选题。格式与下面例子完全一致（一行：标题 — 钩子）。例子：转行第 47 天我删了 200 个收藏教程 — 从收藏到真写代码，我只用了一个方法。不要编号小作文。"
```

**3. 加一句 CoT**

```powershell
python main.py "先用三句话判断每条是否像生活记录而不是鸡汤，再只输出 3 行：标题 — 钩子。赛道：转行学编程。不要输出判断过程以外的长分析。"
```

注意第 3 条里「先判断」和「不要长分析」是在拉锯：看模型是先短短三句再给 3 行，还是又写成昨天那种长文。把现象写进日志。
