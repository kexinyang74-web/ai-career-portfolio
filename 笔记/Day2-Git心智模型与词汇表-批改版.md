## 一、一句话理解（教学内容，保留）

Git 是"存档系统"：把文件夹的每次改动做成存档点，随时能回到任意存档，还能同步到 GitHub。

## 二、三个区域（教学内容，保留）

```text
工作区 ── git add ──> 暂存区 ── git commit ──> 版本库
（编辑中的文件）     （待提交清单）          （永久存档）
```

- 工作区：你正在编辑的文件夹
- 暂存区：你选好"这次要存哪些改动"的清单
- 版本库：真正的存档柜（.git 里的历史）

## 三、本地与远程（教学内容，保留）

- 本地仓库 = 电脑上的存档；远程仓库 = GitHub 上的存档（备份 + 给面试官看）
- `push` = 本地存档上传到 GitHub；`pull` = 把 GitHub 的存档拉回本地
- 记住：**commit 只存在本地，push 才上传**。看到 "ahead by N commits" 就是"本地有 N 条还没上传"

## 四、分支（教学内容，保留）

- `main` = 主时间线
- 分支 = 平行时间线（随便改不破坏主线）
- `merge` = 把分支合并回主线

## 六、自测 5 题批改

**第 1 题：三个区域按什么顺序流转？`git add` 和 `git commit` 各干什么？**

- 你的回答："他可能是按工作区，然后流转到暂存区。暂存区再流转到那个版本库（永久存储区）。git add 的作用就是把你工作区内容上传到暂存区；git commit 的作用就是把你暂存区的内容上传到版本库，也就是本地储存。"

**第 2 题：`git commit` 和 `git push` 有什么区别？**

- 你的回答："这两个区别是不是在于，前者是上传到本地，然后后者他是把本地里面的修改上传到远程仓库云端"
- 批注：✅ **对**。记住一句话：commit = 本地存档，push = 上传云端。

**第 3 题：分支是什么？`merge` 干什么？**

- 你的回答："分支好像就是一个跟备份类似的一个东西，就是相当于把你这个工作状态分出来一份儿完全一样的。但是，你新分出来的这个修改的话，不会影响主线的内容。merge是不是就是把就是主线分出来的内容跟主线合并这一部分，我感觉有点儿混乱"
- 批注：⚠️ 前半句**对**（"复制一份、改分支不影响主线"就是平行世界的直觉，保持住）。merge 不用混乱：**把分支走过的路并入主线，合并后分支的改动成为主线的一部分**。

**第 4 题：冲突什么时候发生？**

- 你的回答："冲突就是你可能在合并的时候会有一些不一样的内容，然后他就会问你批不批准之类的"

## 七、重点再讲（4 处修正点）

1. **branch = 平行世界，不是列表**：从某个存档点"分叉"，主线继续走 A 路线，分支走 B 路线，两边的文件互不干扰。想回主线就切换回来，分支的改动不会丢。
2. **merge = 把分支的路并入主线**：合并后，分支上新增/修改的内容进入主线，主线从此包含这些改动。
3. **冲突解决流程**：冲突时文件里会出现：
   ```text
   <<<<<<< HEAD
   主线版本
   =======
   分支版本
   >>>>>>> branch-name
   ```
   手动删掉不要的一边（或手工合并两边的内容），保留要的，删掉 `<<<<<<<` `=======` `>>>>>>>` 标记，然后 `git add` + `git commit` 完成解决。**不是"批准"**。
4. **commit = 带编号的存档点**：每次 commit 有唯一编号（如 `7a48c37`），是"可回退的存档"，不只是简单"存本地"。

## 八、补充：什么时候用分支 / 节点（实例）

### 分支（branch）——开平行世界去试错

1. **加新功能怕搞坏**：项目一"第 1 版可用"后想加语音输入 → `git checkout -b feature/voice` 在分支里改；成功了 merge 回 main，失败了删掉分支，main 毫发无损。
2. **实验新技术**：想试 LlamaIndex 替换 LangChain，不确定能不能成 → 开 `experiment/llama` 分支实验，不行就删，行就合。
3. **线上/开发并存**：v1 正在被用户使用，要开发 v2 大改版 → main 保持 v1（坏了还能修），`dev/v2` 分支开发，做完再合。类比：正式菜单 vs 后厨研发的新菜。
4. **团队协作（以后工作用）**：每人开自己的分支（feature/小王、feature/小李），各改各的，最后合并到 main。
5. **你现在的情况**：单人学习阶段，main 一条线够用，分支可以先不用——但概念要懂，面试必考。

### 节点（commit）——在每个关键节点存档

1. **改坏了回退**：`git log --oneline` 找到"能用"的存档编号 → `git restore --source=<编号> <文件>` 恢复到那个状态。
2. **对比差异**：`git diff 上次的节点..现在`，看这段时间到底改了什么（写简历、复盘项目时很有用）。
3. **分叉点**：分支不是凭空产生的，它从某个节点"分叉"出去——节点是分支的地基。
4. **里程碑存档**：项目第 1 版完成时 commit 一个"v1 可用"，之后随便折腾都有退路。

**一句话总结**：分支 = 开平行世界去试错，commit = 在每个关键节点存个档。你仓库里现在的 7 个提交（`5d04bbb` → `7a48c37`）就是 7 个存档点，任何一个都能回去。
