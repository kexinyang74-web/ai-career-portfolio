# Day 25 pytest 测试基础

> 第 4 周第 4 天。核心:把"我手动试一下"升级成"写代码替你检查"。配套练习:projects/python-practice/day25/(score_tools.py 被测 + test_score_tools.py 测试)。

## 一、为什么写测试?(动机)

| 手动验证 | 自动化测试 |
|---|---|
| 改完代码自己跑一遍看结果 | 改完跑 `pytest`,机器检查全部 |
| 改 A 功能可能悄悄弄坏 B,察觉不到 | **回归测试**:每次跑,旧功能全部重新验证 |
| 验证 5 个场景要手动改 5 次输入 | 写一次,以后永远自动跑 |

**测试 = 给代码买保险**:今天修的 bug,测试替你保证它这辈子不再犯(Day 24 的 `sum = score` 若有测试,根本活不过第一轮)。

## 二、pytest 认文件的三个规则

1. 文件名以 `test_` 开头 → 才被收集(如 test_score_tools.py)
2. 函数名以 `test_` 开头 → 才被执行(如 test_平均分_正常情况)
3. 断言用 `assert` → `assert 条件, "失败时显示的话(可选)"`

## 三、怎么跑(在 day25 目录下,二选一)

```powershell
.\.venv\Scripts\python.exe -m pytest   # 不激活也能跑
# 或先激活 venv,再直接敲: pytest
```

pytest 自动扫描当前目录所有 test_ 开头的文件(`collected 7 items` = 找到 7 道题)。

## 四、输出读法

**全绿**:`test_score_tools.py .......` → `7 passed in 0.02s`
(每个 `.` = 一个测试通过)

**有失败**:`F......`(F = 失败,红)
```text
>       assert 计算平均分([80, 90, 100]) == 90.0
E       assert 33.333333333333336 == 90.0          ← 实际 ≠ 期望
E        +  where 33.333333333333336 = 计算平均分([80, 90, 100])  ← 实际值从哪来
```
| 行 | 含义 |
|---|---|
| `>` | 断言的源代码位置(文件:行号) |
| `E` 断言行 | **左边 = 实际**,右边 = 期望 |
| `E` where 行 | pytest 解释实际值是从哪来的 |

底部:定位写法 `test_score_tools.py::test_平均分_正常情况`(文件::函数)+ 总账 `1 failed, 6 passed`。

## 五、红 → 绿闭环(回归测试的完整价值)

改坏 `total = score` → 跑 → 红(1 failed 6 passed)→ 读报告定位 → 改回 `total += score` → 跑 → 全绿。
**测试抓住 bug → 修复 → 测试确认安全**,以后每次改动都这么兜底。

## 六、为什么"只挂 1 个"?(测试的边界思想)

- 单个成绩 `[5]` 侥幸通过:一轮循环里覆盖和累加结果一样 → **没走到坏代码的测试永远绿着**
- 空列表/等级/过滤没碰到那行代码
- 启示:① 测试覆盖面有限,不是万能;② 要故意写**边界用例**(单个、空、59/60 分)逼出边角;③ 测试相互独立,一个红不影响其他跑(对比程序崩溃直接全停)

## 七、Windows 斜杠坑(今天意外收获)

docstring 里写 `\.venv\Scripts\` → `SyntaxWarning: invalid escape sequence`:
Python 字符串里 `\` 是**转义符**(`\n`=换行),`\.` 不是合法转义 → 警告。
修复三选一:① **路径写正斜杠** `.venv/Scripts/`(Windows 全兼容,首选);② 字符串加 `r`(raw);③ `\\` 双反斜杠。
区分:**终端命令用反斜杠(PowerShell 的规矩),Python 字符串里用正斜杠**。

## 八、速查

```text
pytest                    跑当前目录所有测试(自动找 test_*.py)
pytest 文件名.py           只跑指定文件
collected 7 items         找到 7 个测试
. = 过  F = 挂            进度条
E 行:实际 != 期望          失败原因
文件::函数                失败测试的精确地址
```
