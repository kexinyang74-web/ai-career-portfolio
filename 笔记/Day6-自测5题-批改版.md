## 一、核心要点（一页速记）

### git status 四行分别是什么

- `On branch main`：当前在 main 分支
- `Your branch is ahead of 'origin/main' by 1 commit`：本地比云端多 1 个提交，还没 push
- `Changes not staged for commit: modified: xxx`：xxx 被改过了，但还没 `git add`（没进暂存区）
- `Untracked files:`：新文件，Git 完全没见过，还没跟踪
- 下一步：`git diff` 看改了啥 → `git add 文件` → `git commit` → `git push`

### 向 AI 下指令的公式

- 对象（今天所有改动）+ 动作（commit + push）+ 期望结果（把 status/log 贴给你验收）
- 参考版："把今天所有改动提交并推送到 ai-career-portfolio 的 main 分支，完成后把 git status 和 git log --oneline 的输出贴给我验收。"

### venv 三命令（检查点 4，必须亲手跑一遍）

```powershell
.\.venv\Scripts\Activate.ps1    # ① 激活（在项目根目录，成功后命令行开头出现 (.venv)）

```

> 小区别：`pip list` 是表格；`pip freeze` 是 requirements 格式（带版本号），装完依赖后常用它生成 requirements.txt。

### 密钥安全三板斧

- 为什么不能提交：`.env` 进 git → 同步到远端公开仓库 → API 密钥暴露 → 资金损失
- 两条确认命令：`git status`（列表里没有 .env）+ `git check-ignore .env`（输出 `.env` = 已忽略）
- 已提交的补救两步：`git rm --cached .env`（磁盘文件保留）+ 去 API 平台换新密钥
